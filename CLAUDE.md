# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за проект

Telegram-бот оповещений о землетрясениях в Грузии. Работает как Cloudflare Worker: `fetch` принимает webhook Telegram (grammY), `scheduled` раз в минуту по Cron Trigger парсит таблицу землетрясений с сайта Ilia State University и рассылает алерты подписанным чатам. Состояние — в Cloudflare D1 через Kysely.

## Команды

- `npm run dev` — локальный запуск (`wrangler dev`)
- `npm test` / `npm run test:watch` — vitest
- `npx vitest run src/domain/geo.test.ts` — один тестовый файл
- `npm run typecheck` — `tsc --noEmit`
- `npm run db:migrate:local` / `npm run db:migrate:remote` — миграции D1
- `npm run deploy` — `wrangler deploy`
- `npx wrangler deploy --dry-run --outdir=.wrangler/dry-run` — проверить сборку и размер бандла, не деплоя
- `npx wrangler d1 execute earthquake-bot --remote --command "SELECT ..."` — запрос к боевой базе
- `npx wrangler tail` — живые логи (историю не показывает; логи также копятся в дашборде, включён `[observability]`)

## Архитектура

Слои, от внешнего мира внутрь:

- `src/scraper/` — загрузка страницы (`fetchPage.ts`, нативный fetch с retry) и парсинг таблицы (`parseTable.ts`, ручное сканирование строки без DOM-библиотеки). Не знает про Telegram и БД.
- `src/domain/` — чистые функции без побочных эффектов: время (`time.ts`), координаты и ссылки на карту (`geo.ts`), фильтр подписки (`filters.ts`), статистика (`stats.ts`).
- `src/db/` — единственное место, работающее с D1: `client.ts` (Kysely + kysely-d1), `schema.ts` (типы таблиц), `repositories/*`.
- `src/poller/` — оркестрация: `checkForNewEarthquakes.ts` (fetch → parse → insert → рассылка) и `alertDispatcher.ts` (фильтрация подписок и отправка).
- `src/bot/` — UI: `bot.ts` (команды, middleware регистрации чата), `menus.ts` (@grammyjs/menu).
- `src/templates/` — тексты на русском и HTML-шаблоны сообщений.
- `src/worker.ts` — точка входа Worker'а (`fetch` + `scheduled`).

Слой БД оперирует snake_case (как в таблицах), скрапер — camelCase (`ParsedEarthquake`). Преобразование живёт в репозиториях. Шаблоны сообщений намеренно принимают форму строки БД (`EarthquakeLike` в snake_case), чтобы результат репозитория уходил в рендер без промежуточного маппинга.

## Тесты

Покрыты два слоя. `src/domain/**` и `src/scraper/parseTable.ts` — обычные unit-тесты рядом с кодом. `src/db/repositories/repositories.test.ts` гоняет настоящие репозитории против настоящей SQLite (`node:sqlite`) через шим, повторяющий контракт D1: kysely-d1 дёргает только `prepare(sql).bind(...params).all()`. Полноценный Workers-рантайм для этого не нужен, vitest остаётся в обычном Node.

Схема в шиме поднимается из боевой `migrations/0001_init.sql`, поэтому расхождение миграции с `schema.ts` ловится тестом. Контроль внешних ключей включён (`PRAGMA foreign_keys = ON`), как в D1.

Третий покрытый кусок — навигация по меню (`src/bot/menuFlow.test.ts`). Он гоняет настоящие хендлеры (`createBot`) против той же SQLite через D1-шим, а вызовы Telegram API перехватывает транcформером grammY, поэтому в сеть не ходит и боевой токен не нужен. Стережёт ровно то, что не видно ни типам, ни глазу при чтении диффа: что кнопки меню зовут `editMessageText`, а не `ctx.reply`.

Не покрыты намеренно: `fetchPage.ts` (сетевой ввод-вывод) и остальной `src/bot/**` (тексты и вёрстка сообщений — проверяется руками в Telegram).

## Ключевые механизмы

Эти вещи размазаны по нескольким файлам, и их легко сломать, не заметив.

**Дедупликация событий** — по `dedupe_key`: id события из ссылки источника (`id:588000`), с откатом на составной ключ время+координаты+магнитуда. Вставка идемпотентна (`onConflict().doNothing()`), `insertIfNew` возвращает `true` только для реально новых строк.

**Двойная защита от рассылки истории.** Cron тикает раз в минуту, поэтому любая ошибка здесь означает спам в чаты каждую минуту. Защит две, и они независимы:
1. Холодный старт (`countEvents === 0`) наполняет базу и помечает всё разосланным без отправки.
2. `MAX_ALERT_AGE_MS` (6 часов) в `checkForNewEarthquakes.ts` — событие старше порога помечается разосланным без отправки. Нужно на случай, когда первый тик убит между вставками и пометкой: транзакций в D1 нет, откатывать нечем, и вторая защита ловит то, что упустила первая.

**Разбор таблицы без DOM-библиотеки.** `parseTable.ts` сканирует строку регулярками и не тянет cheerio. Это не микрооптимизация: инициализация cheerio на холодном изоляте одна съедала весь CPU-бюджет free-плана (~10 мс), и cron падал с `outcome: exceededCpu` на каждом тике — независимо от того, сколько HTML ему дали на вход. Ручной разбор живой страницы стоит ~1 мс. Не возвращать сюда cheerio, jsdom и прочие парсеры HTML; это проверяется тестом.

Разбор держится на трёх вещах, каждую из которых легко сломать:
- `stripInertMarkup` вырезает комментарии и содержимое `<script>`/`<style>` **до** поиска таблицы. Маркер `eartquakes-table` встречается на живой странице внутри `<style>`, а таблица-приманка с тем же классом в комментарии или в строковом литерале скрипта иначе увела бы разбор не туда.
- `sliceInner` ищет закрывающий тег с учётом вложенности, а не по первому вхождению. Вложенная таблица-виджет внутри `tbody` иначе обрывала бы срез на своём `</table>`, молча теряя все настоящие строки после неё.
- Сущности декодируются вручную (`decodeEntities`) — DOM-библиотека делала это сама.

**Доступ к меню держится на reply-клавиатуре.** Инлайн-кнопки живут в конкретном сообщении и уезжают вверх по истории — особенно быстро, потому что алерты рассылаются каждую минуту. Поэтому кнопка «☰ Меню» — обычная reply-клавиатура (`src/bot/keyboard.ts`), закреплённая у поля ввода, и её прицепляют все команды, у которых нет своей инлайн-разметки; так она досевается и тем, кто подписался до её появления. По той же причине кнопки главного меню правят своё сообщение через `editMessageText`, а не отвечают новым: иначе меню снова начнёт плодить сообщения. Правки идут через `editIgnoringNoChange`, которая гасит ошибку Telegram «message is not modified» на повторном нажатии той же кнопки — узко, по тексту ошибки; расширять её до catch-all нельзя, иначе сломанное редактирование станет невидимым.

**Ошибки вебхука ловятся в `worker.ts`, а не через `bot.catch`.** `webhookCallback` дёргает `bot.handleUpdate` напрямую, а тот всегда перебрасывает ошибку наружу: `errorHandler` из `bot.catch` работает только при long polling, которого здесь нет. `bot.catch` в этом проекте — мёртвый код, и однажды он уже создал ложное впечатление, что ошибки залогированы. Ответ на упавший апдейт — 200, а не 500: на любой другой код Telegram повторит тот же апдейт, а хендлер к моменту падения мог уже отправить часть сообщений.

**Сопоставление колонок** — по нормализованному тексту заголовка (пробелы вырезаны, lowercase), никогда по индексу. В источнике заголовки идут с ведущими пробелами и без пробела перед скобкой: `<th > Magnitude(ml)</th>`.

**Ячейка региона** содержит постороннюю ссылку на опрос — она вырезается при парсинге; не полагаться на сырой текст ячейки.

## Важные ограничения

- Бандл Worker'а на free-плане ограничен 1MB gzip (сейчас ~172 КБ) — не добавлять тяжёлые зависимости; Prisma, luxon, axios, jsdom здесь неприменимы. Часовой пояс — нативным `Intl`, HTTP — нативным `fetch`.
- CPU-время на вызов ~10мс на free-плане, включая cron-тики. Сетевое ожидание не считается, парсинг считается.
- D1 не поддерживает транзакции — использовать идемпотентные операции, не `db.transaction()`. Как следствие, рассылка имеет семантику at-least-once: при падении между отправкой и `markNotified` алерт уйдёт повторно.
- Все пользовательские тексты — на русском, в `src/templates/texts.ts`; в слое бота литералов сообщений не заводить (подписи кнопок меню — исключение, они часть определения меню). Данные из источника всегда проходят через `escapeHtml()`.
- Деактивировать подписку можно только по 403 и по узкому набору 400 («chat not found», «group chat was upgraded»). Широкая обработка 400 отпишет разом всю базу, потому что текст сообщения общий для всех получателей в цикле.

## Деплой

`BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` обязательны (`parseEnv` падает без них) и задаются через `wrangler secret put`. Значение `secret_token` в запросе `setWebhook` обязано совпадать с сохранённым секретом, иначе Telegram получает 401 на каждый апдейт и бот выглядит мёртвым без единой ошибки в логах. Полная последовательность — в [README.md](README.md).
